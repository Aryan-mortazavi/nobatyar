# 📅 سامانه رزرو آنلاین نوبت مبتنی بر تلگرام

**Telegram-Based Online Appointment Booking System**

ربات تلگرامی + پنل مدیریت وب برای رزرو نوبت (مشاوره، ویزیت، آموزش و…) با
تقویم شمسی، ساعات کاری پویا، لیست انتظار و یادآور خودکار.

> این پروژه کاملاً **آماده اجرا** است، رابط کاربری آن **۱۰۰٪ فارسی/شمسی** است
> و **هیچ سامانه پرداختی** در آن وجود ندارد (رزرو با ثبت نوبت تمام می‌شود).

## ۱. معرفی کوتاه

کاربر وارد ربات تلگرام می‌شود، با دکمه «ارسال شماره» ثبت‌نام می‌کند و در چند
گام ساده نوبت خود را می‌گیرد:

**انتخاب خدمت ← انتخاب کارشناس ← انتخاب تاریخ شمسی ← انتخاب ساعت ← تأیید ←
دریافت کد رهگیری `APT-12345`**

مدیر هم از دو جا می‌تواند سیستم را اداره می‌کند:

* پنل تلگرامی با دستور `/admin`
* پنل وب (FastAPI) با مسیرهای `/dashboard`، `/users`، `/services`، …

## ۲. قابلیت‌ها

### کاربر عادی
* ثبت‌نام با دکمه Contact تلگرام (بدون تایپ شماره)
* منوی اصلی ۷ دکمه‌ای: **رزرو نوبت، نوبت‌های من، تغییر وقت، لغو نوبت، پروفایل، پشتیبانی، درباره ما**
* رزرو چندمرحله‌ای با FSM (State) و همیشه در دسترس بودن دکمه‌های «بازگشت» و «انصراف»
* تقویم شمسی فقط با روزهای قابل رزرو (روزهای گذشته/تعطیل/پر نمایش داده نمی‌شوند)
* لیست ساعت‌های آزاد به‌صورت **پویا** محاسبه می‌شود (نه ساعت‌های ثابت از پیش تعریف‌شده)
* تغییر وقت (لغو بازه قبلی + رزرو بازه جدید در یک تراکنش)
* لغو نوبت با قانون «حداقل ساعت باقی‌مانده» (قابل تنظیم توسط مدیر)
* لیست انتظار: اگر ساعت دلخواه پر بود، کاربر در لیست انتظار می‌ماند و هنگام آزاد
  شدن بازه، پیام «رزرو این ساعت» دریافت می‌کند
* یادآوری خودکار ۲۴ ساعته و ۱ ساعته قبل از نوبت (بدون تکرار)
* تیکت پشتیبانی و دریافت پاسخ مدیر
* ویرایش پروفایل (نام، نام خانوادگی، شماره)

### مدیر
* داشبورد با آمار و نمودار (Chart.js)
* مدیریت کاربران (فعال/غیرفعال، نقش)
* CRUD کامل خدمات: نام، توضیح، مدت (دقیقه)، قیمت (اطلاعاتی)، فعال/غیرفعال
* CRUD کامل کارشناسان + انتخاب خدمات هر کارشناس (ارتباط M:N)
* ساعات کاری هفتگی به تفکیک روز هفته ایرانی (شنبه=۰) + زمان استراحت
* مدیریت تعطیلات (یک روز کامل بدون نوبت)
* مشاهده/تأیید/لغو/انجام شده/عدم مراجعه نوبت‌ها + صفحه‌بندی
* لیست انتظار، تیکت‌های پشتیبانی، گزارش روزانه و ماهانه شمسی
* تنظیمات سیستم (نام مرکز، تلفن، آدرس، متن «درباره ما»، مدت بازه، حداکثر روز رزرو،
  حداقل ساعت لغو، تأیید خودکار)
* همه دکمه‌های پنل واقعاً کار می‌کنند و همه لیست‌ها صفحه‌بندی دارند

> **نکته:** شناسه ادمین‌ها فقط از فایل `.env` خوانده می‌شود؛ هیچ شناسه‌ای در
> کد هاردکد نشده است. نقش‌ها قابل توسعه‌اند (`user`، `admin` و `moderator` رزرو شده).

## ۳. معماری پروژه

```
        ┌────────────────────┐
        │  Telegram (API)    │
        └─────────▲──────────┘
                  │ Long Polling (aiogram 3)
        ┌─────────┴──────────────────────────────┐
        │  یک پروسه (main.py)                   │
        │  ┌──────────────┐  ┌────────────────┐  │
        │  │  Dispatcher  │  │ FastAPI/uvicorn│  │
        │  │  Handlers    │  │  پنل وب        │  │
        │  └──────┬───────┘  └───────┬────────┘  │
        │         └──────────┬───────┘           │
        │              ┌─────▼──────┐            │
        │              │  Services  │  (قوانین)  │
        │              └─────┬──────┘            │
        │              ┌─────▼──────┐            │
        │              │ APScheduler│ یادآوری    │
        │              └────────────┘            │
        └──────────────────┬─────────────────────┘
                    ┌──────▼──────┐
                    │ SQLite +    │  SQLAlchemy 2
                    │ Alembic     │
                    └─────────────┘
```

* **لایه `handlers/`** فقط ورودی/خروجی تلگرام را مدیریت می‌کند (UI).
* **لایه `services/`** تمام قوانین کسب‌وکار را دارد (اعتبارسنجی، رزرو، لغو،
  ساعات کاری، لیست انتظار، گزارش). این لایه از تلگرام کاملاً جداست و همان
  لایه‌ای است که تست‌ها روی آن نوشته شده‌اند.
* **لایه `web/`** پنل مدیریت است و از همان `services/` استفاده می‌کند.
* **لایه `database/`** مدل‌ها، اتصال و کوئری‌های گزارش است.

## ۷. تنظیمات فایل `.env`

```powershell
Copy-Item .env.example .env     # یا از فایل .env آماده همین پروژه استفاده کنید
notepad .env
```

| کلید | توضیح |
|---|---|
| `BOT_TOKEN` | توکن ربات از `@BotFather` — **الزامی برای اجرای ربات** |
| `ADMIN_IDS` | شناسه تلگرام مدیر(ها) با ویرگول جدا شود؛ مثلاً `123456789,987654321` |
| `SECRET_KEY` | یک رشته تصادفی بلند برای کوکی پنل وب |
| `WEB_ADMIN_USERNAME` / `WEB_ADMIN_PASSWORD` | نام کاربری و رمز پنل وب |
| `DATABASE_URL` | مسیر دیتابیس (پیش‌فرض `sqlite:///./data/app.db`) |
| `TIMEZONE` | پیش‌فرض `Asia/Tehran` |
| `WEB_HOST` / `WEB_PORT` | آدرس و پورت پنل وب |

> ⚠️ فایل `.env` در `.gitignore` قرار دارد و نباید هرگز در گیت قرار گیرد.
> رمز و توکن هیچ‌جا در سورس هاردکد نشده است.

بدون `BOT_TOKEN` برنامه با پیام روشن زیر متوقف می‌شود (نه خطای عجیب):

```
RuntimeError: BOT_TOKEN is empty - copy .env.example to .env and set your token.
```

## ۸. پایگاه داده و Alembic

### جدول‌ها (۱۲ جدول)
`users`، `services`، `staffs`، `staff_services` (M:N)، `working_hours`،
`break_times`، `holidays`، `appointments`، `waitlist`، `support_tickets`،
`notifications`، `settings`

### نکات مهم طراحی
* دیتابیس تاریخ/ساعت **میلادی (UTC)** را ذخیره می‌کند و **همه نمایش‌ها شمسی** است.
* ستون `appointments.slot_key` با قالب `کارشناس:تاریخ:ساعت` و ایندکس **UNIQUE**
  دارد؛ هنگام لغو نوبت `NULL` می‌شود تا بازه دوباره قابل رزرو شود.
* `PRAGMA foreign_keys=ON`، `busy_timeout=30000` و `journal_mode=WAL` فعال است.
* هر تست روی یک دیتابیس موقت جداگانه اجرا می‌شود و به `data/app.db` دست نمی‌زند.

### دستورات Alembic

```powershell
# ساخت جدول‌ها با مهاجرت اولیه
..\venv\Scripts\python.exe -m alembic upgrade head

# ساخت مهاجرت جدید بعد از تغییر مدل‌ها
..\venv\Scripts\python.exe -m alembic revision --autogenerate -m "change description"

# بازگشت یک مرحله
..\venv\Scripts\python.exe -m alembic downgrade -1
```

> `init_db()` هنگام اجرا جدول‌ها را به‌صورت idempotent می‌سازد؛ یعنی اجرای
> مکرر `python main.py` بدون Alembic هم مشکلی ایجاد نمی‌کند.

## ۱۳. جریان رزرو نوبت

```
/start → دکمه «ارسال شماره» → ثبت‌نام → منوی اصلی
   ↓
رزرو نوبت
   1) خدمت      (لیست خدمات فعال)
   2) کارشناس   (فقط کسانی که آن خدمت را ارائه می‌دهند — ارتباط M:N)
   3) تاریخ     (تقویم شمسی، فقط روزهای قابل رزرو)
   4) ساعت      (بازه‌های آزادِ محاسبه‌شده)
   5) خلاصه + تأیید
   ↓
ثبت نوبت → کد رهگیری APT-XXXXX → پیام تأیید
```

وضعیت‌ها و برچسب فارسی آن‌ها:

| وضعیت | برچسب فارسی |
|---|---|
| `pending` | در انتظار تأیید |
| `confirmed` | تأیید شده |
| `cancelled` | لغو شده |
| `completed` | انجام شده |
| `no_show` | عدم مراجعه |

(در حالت پیش‌فرض، نوبت‌ها بلافاصله `confirmed` می‌شوند؛ با خاموش کردن
«تأیید خودکار» در تنظیمات، وضعیت اولیه `pending` خواهد بود.)

## ۱۴. جلوگیری از رزرو همزمان

**مسئله:** دو کاربر ممکن است دقیقاً یک ساعت را هم‌زمان انتخاب کنند.

**راه‌حل: سه لایه محافظت**

1. **بازبینی داخل همان تراکنش** — پیش از `INSERT` دوباره بررسی می‌شود که بازه
   هنوز آزاد است (`slot_service.is_slot_available`).
2. **محدودیت دیتابیس** — ایندکس `UNIQUE` روی `appointments.slot_key`
   (`کارشناس:تاریخ:HH:MM`)؛ دو رکورد هم‌شکل اصلاً نمی‌توانند ذخیره شوند.
3. **تبدیل خطای پایگاه داده به پیام فارسی** — اگر `IntegrityError` رخ داد،
   به‌جای نمایش خام خطای فنی، پیام زیر به کاربر نشان داده می‌شود:

   > ⛔ این بازه زمانی هم‌زمان توسط کاربر دیگری رزرو شد. لطفاً ساعت دیگری انتخاب کنید.

تست `test_double_booking.py` این سه لایه را با **۴ رشته هم‌زمان** هم آزمایش می‌کند.

## ۱۵. ساعات کاری، تعطیلات، لیست انتظار و یادآورها

### محاسبه پویای ساعت‌های آزاد (هیچ ساعت ثابتی در کد نیست)

```
ساعات کاری روز  −  استراحت‌ها  −  نوبت‌های ثبت‌شده  −  ساعت‌های گذشته
        ↓
پیمایش با گام = «مدت خدمت (دقیقه)»
        ↓
لیست بازه‌های آزاد آن روز
```

* هفته ایرانی: شنبه=۰ … جمعه=۶ (روز بدون ردیف `working_hours` یعنی تعطیل).
* تعطیلات رسمی (`holidays`) کل آن روز را می‌بندد.
* قانون «حداکثر ۳۰ روز آینده» (قابل تغییر در تنظیمات) هم اعمال می‌شود.

### لیست انتظار
* اگر بازه‌ای پر بود، کاربر می‌تواند در لیست انتظار ثبت شود.
* هنگام **لغو** یک نوبت، اولین نفر مناسب آزاد می‌شود و پیام «رزرو این ساعت»
  با دکمه Inline دریافت می‌کند.
* رکوردهای منقضی به‌صورت دوره‌ای وضعیت `expired` می‌گیرند.

### یادآوری (APScheduler)
* هر ۵ دقیقه بررسی می‌شود: یادآور ۲۴ ساعته و ۱ ساعته.
* فلگ‌های `reminder_24h_sent` / `reminder_1h_sent` از **تکرار** جلوگیری می‌کنند.
* نوبت‌های لغوشده اصلاً یادآوری نمی‌شوند.

## ۱۷. عیب‌یابی

| مشکل | راه‌حل |
|---|---|
| `BOT_TOKEN is empty` | فایل `.env` را بسازید و توکن را بگذارید |
| خطای `Activate.ps1 ... running scripts is disabled` | `Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass` |
| پورت ۸۰۰۰ اشغال است | `WEB_PORT=8001` را در `.env` عوض کنید |
| `/admin` در تلگرام باز نمی‌شود | شناسه تلگرامتان را در `ADMIN_IDS` بگذارید و ربات را ری‌استارت کنید |
| خطای دوره‌ای `database is locked` | نسخه قدیمی `data/app.db` را ببندید؛ WAL و `busy_timeout` فعال‌اند |
| می‌خواهید از صفر شروع کنید | `data\app.db` را حذف کنید (یا `data\app.db-wal` و `-shm` را هم) |
| لاگ‌ها | `logs/app.log` (بدون هیچ توکن/رمزی) |

### الف) اسکریپت ۵ دقیقه‌ای (به همین ترتیب بگویید)

**۱) مسئله (۳۰ ثانیه)**
«رزرو نوبت به‌صورت تلفنی و دستی باعث خطای اپراتیر، دبل‌بوتینگ و اتلاف وقت
می‌شود. هدف ما ساخت یک سامانه رزرو آنلاین بود که کاربر فقط با تلگرام کار کند.»

**۲) راه‌حل و معماری (۶۰ ثانیه)**
«سه لایه دارد: ربات تلگرام با aiogram، پنل مدیریت وب با FastAPI، و یک

(`services`) استفاده می‌کنند؛ یعنی قوانین یک بار نوشته شده و هر دو جا از آن

**۳) جریان اصلی (۶۰ ثانیه)**
«کاربر با دکمه شماره ثبت‌نام می‌کند، بعد خدمت → کارشناس → تاریخ شمسی → ساعت
→ تأیید را انتخاب می‌کند و کد رهگیری `APT-XXXXX` می‌گیرد. مهم‌ترین بخش،
محاسبه **پویای** ساعت‌های آزاد است: ساعات کاری منهای استراحت، منهای نوبت‌های
ثبت‌شده، منهای ساعت‌های گذشته، با گامِ مدتِ خدمت. یک ساعت ثابت در کد نوشته

**۴) چالش فنی اصلی (۹۰ ثانیه)** ← این بخش نمره بیشتری دارد
«دو نفر ممکن است دقیقاً یک لحظه یک ساعت را انتخاب کنند. سه لایه گذاشته‌ام:
۱. بازبینی دسترس‌پذیری داخل همان تراکنش، ۲. ایندکس `UNIQUE` روی `slot_key` در

4. لغو نوبت از پنل وب → نمایش پیام لیست انتظار در تلگرام

## ۱۹. محدودیت‌ها و توسعه‌های آینده

* **بدون پرداخت:** طبق دامنه پروژه، هیچ درگاه/جدول/ماژول پرداختی وجود ندارد.
* فعلاً فقط SQLite؛ برای استفاده عملیاتی چندکاربره می‌توان به PostgreSQL ارتقا داد.
* نوبت‌های چندروزه/تکرارشونده (series) هنوز پیاده نشده‌اند.
* وب‌هوک به‌جای Long Polling برای محیط‌های production.
* احراز هویت دومرحله‌ای و نقش سوم (`moderator` از قبل رزرو شده).
* خروجی اکسل گزارش‌ها و یادکننده پیامکی.
